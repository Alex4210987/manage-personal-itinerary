# 证据、去重与状态

## 来源覆盖

为每个来源记录：source_key、身份的最小化显示、连接方式、请求窗口、实际覆盖窗口/分页、attempted_at、last_success_at、状态（ok / partial / blocked / not_checked）及失败原因。空结果必须附已成功执行的查询范围；未能读取、只读到首页或未翻页不能冒充全量空结果。

把四层验收分开：
1. account_login：登录身份可见；
2. data_read：目标数据实际可读；
3. scheduled_execution：计划已保存且至少有一次实际运行回执；
4. device_delivery：用户或可用设备证据确认通知送达。

不以较低层的通过推断较高层通过。时间戳带时区，摘要使用实际结果而不是计划时间。

## 事项证据

每项至少保留：稳定内部键、来源记录指针、标题、事项类型、原始时间表达、来源更新时间、提取时间、时区证据、规范化开始/结束或截止、推算依据、置信状态、处置状态、日历关联和最近核验。

- 只保存最小必要的摘录和安全链接；去掉分享令牌、认证查询参数、会议密码等秘密。不要在可复用 Skill 或公开产物中保存个人账号、邮件、会议号或课程表。
- 原文明确给出的时间标为 explicit；依据已核实规则算得的时间标为 derived 并记录表达式与锚点；缺信息标为 needs_confirmation。不要让“高置信度”替代证据。
- 以 IANA 时区或提供者可靠时区标识记录规则，同时保存规范化时间与原始钟点。界面显示时区与实际事件时区可能不同，先验证再换算，避免重复加减时差。
- 日期明确但钟点未知时，保留 date-only 精度，不自行补 23:59、上课开始或当前钟点。若需日历表达，获得用户对全天“截止日期，时刻待确认”的同意。
- “报告后一周交”必须先核实实际报告日期及“一周”的语义，记录 anchor + 7 calendar days；若锚点是日期而非时刻，结果仍只有日期。报告延期后重算并核对原截止说明，不沿用旧值。
- 课程周次使用该学期正式校历的第一周锚点及已知例外；核对单双周、节假日、调休、补课和某次取消。不能凭“周三上课”无限重复，也不能把课表的结束周当每门课的默认结束周。

## 合并与处置

先用提供者稳定 ID、课程作业 ID 或日历 UID；跨来源再比较课程/组织者、事项类型、原始主题、日期/时段和来源交叉指向。标题相似不是充分条件；同一系列的不同场次保留 occurrence_key。

合并证据而不是制造副本。相互矛盾的时间保留两个值和各自出处；优先核验正式详情页、明确修订通知及更新时间，不静默挑选“最新抓取”的值。

将 disposition 与 deadline 分离：active / completed / dismissed / needs_confirmation。对 dismissed 保存用户决定时间、范围（单次或系列）和理由（若用户提供）；同一事项新邮件、重复公告、未读状态变化不会解除忽略。用户明确重新打开才转回 active；若新证据实质改变事项，询问是否重新处理，不能擅自重启提醒。

未读是阅读状态；0 分可能是未批改、计分设置或真实成绩；空分也不表示未交。只有平台明确提交/缺交状态、提交记录或用户确认可支持完成判断。信息不足时写“提交情况待核实”，不要写“你漏交了”。

## 台账与可审计性

使用用户认可的私有存储位置，沿用已存在的台账，不另建竞争真相源。模板是字段起点而非强制数据库；可删去无关字段，但保留证据、处置、覆盖、写入和通知去重关联。

提醒键建议为 item_key + occurrence_key + deadline_revision + stage + channel；记录 planned / sent / failed / canceled 及实际时间、回执。修改截止后使旧计划失效，再计算新阶段；不要一次补发所有已过去的提醒。
